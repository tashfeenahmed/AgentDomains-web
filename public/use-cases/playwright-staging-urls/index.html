2. 4-Step MCP Tool-Call Transcript

Here is the exact sequence an agent executes against https://mcp.agentdomains.co (or local stdio npx -y agentdomains-mcp):

STEP 1check_availability
MCP Call → check_availability 
{
  "tool": "check_availability",
  "arguments": {
    "label": "e2e-stage",
    "domain": "makes.fyi"
  }
}
// Response:
{
  "fqdn": "e2e-stage.makes.fyi",
  "available": true,
  "reason": "available"
}
STEP 2claim_domain
MCP Call → claim_domain 
{
  "tool": "claim_domain",
  "arguments": {
    "label": "e2e-stage",
    "domain": "makes.fyi",
    "email": "ops@example.com"
  }
}
// Response:
{
  "fqdn": "e2e-stage.makes.fyi",
  "status": "claimed",
  "confirm_within_days": 30
}
STEP 3set_proxy
MCP Call → set_proxy 
{
  "tool": "set_proxy",
  "arguments": {
    "label": "e2e-stage",
    "domain": "makes.fyi",
    "origin": "e2e-stage.fly.dev"
  }
}
// Response:
{
  "ok": true,
  "fqdn": "e2e-stage.makes.fyi",
  "origin": "e2e-stage.fly.dev",
  "https": "https://e2e-stage.makes.fyi"
}
STEP 4Live Verification (200 OK)
Verify live HTTPS response 
curl -fsSI https://e2e-stage.makes.fyi
# HTTP/2 200
# content-type: application/json
# strict-transport-security: max-age=31536000

3. Clean Teardown (GitHub Action & CLI)

Always invoke `agentdomains delete` in a CI `if: always()` cleanup step. Always delete the DNS/proxy mapping before deleting your upstream cloud resource to prevent dangling subdomain takeovers.

.github/workflows/teardown-domain.yml 
name: Teardown e2e-stage
on:
  workflow_dispatch:
  pull_request:
    types: [closed]
jobs:
  cleanup:
    runs-on: ubuntu-latest
    steps:
      - name: Delete AgentDomains hostname before destroying compute
        env:
          AGENTDOMAINS_API_KEY: ${{ secrets.AGENTDOMAINS_API_KEY }}
        run: |
          curl -fsSL -X DELETE \
            -H "Authorization: Bearer $AGENTDOMAINS_API_KEY" \
            "https://api.agentdomains.co/v1/subdomains/e2e-stage"
      # Or with the Go CLI:
      # agentdomains delete e2e-stage
