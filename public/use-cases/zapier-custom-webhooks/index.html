2. 4-Step MCP Tool-Call Transcript

Here is the exact sequence an agent executes against https://mcp.agentdomains.co (or local stdio npx -y agentdomains-mcp):

STEP 1check_availability
MCP Call → check_availability 
{
  "tool": "check_availability",
  "arguments": {
    "label": "zap-bridge",
    "domain": "makes.fyi"
  }
}
// Response:
{
  "fqdn": "zap-bridge.makes.fyi",
  "available": true,
  "reason": "available"
}
STEP 2claim_domain
MCP Call → claim_domain 
{
  "tool": "claim_domain",
  "arguments": {
    "label": "zap-bridge",
    "domain": "makes.fyi",
    "email": "ops@example.com"
  }
}
// Response:
{
  "fqdn": "zap-bridge.makes.fyi",
  "status": "claimed",
  "confirm_within_days": 30
}
STEP 3set_proxy
MCP Call → set_proxy 
{
  "tool": "set_proxy",
  "arguments": {
    "label": "zap-bridge",
    "domain": "makes.fyi",
    "origin": "zap-bridge.up.railway.app"
  }
}
// Response:
{
  "ok": true,
  "fqdn": "zap-bridge.makes.fyi",
  "origin": "zap-bridge.up.railway.app",
  "https": "https://zap-bridge.makes.fyi"
}
STEP 4Live Verification (200 OK)
Verify live HTTPS response 
curl -fsSI https://zap-bridge.makes.fyi
# HTTP/2 200
# content-type: application/json
# strict-transport-security: max-age=31536000

3. Clean Teardown (GitHub Action & CLI)

Pause Zaps pointing at the endpoint before calling `agentdomains delete`. Always delete the DNS/proxy mapping before deleting your upstream cloud resource to prevent dangling subdomain takeovers.

.github/workflows/teardown-domain.yml 
name: Teardown zap-bridge
on:
  workflow_dispatch:
  pull_request:
    types: [closed]
jobs:
  cleanup:
    runs-on: ubuntu-latest
    steps:
      - name: Delete AgentDomains hostname before destroying compute
        env:
          AGENTDOMAINS_API_KEY: ${{ secrets.AGENTDOMAINS_API_KEY }}
        run: |
          curl -fsSL -X DELETE \
            -H "Authorization: Bearer $AGENTDOMAINS_API_KEY" \
            "https://api.agentdomains.co/v1/subdomains/zap-bridge"
      # Or with the Go CLI:
      # agentdomains delete zap-bridge
