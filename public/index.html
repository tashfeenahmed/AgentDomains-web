// quickstart

      
Two commands to a live domain

      
Install the CLI once, then your agent claims names whenever it ships something.
      The claim writes the record and the hostname resolves on the public internet in seconds — no
      registrar, no dashboard, no waiting on a human.

    

    

      # install the CLI

      $ go install github.com/tashfeenahmed/AgentDomains/cmd/agentdomains@latest


      # point a domain at the site your agent just built

      $ agentdomains claim myapp --email you@example.com --domain agentdomains.co --type A --content 203.0.113.10

      ✓ myapp.agentdomains.co is live on the public internet
    

  


  

    
// MCP

    
Works over MCP

    
Hosted Streamable HTTP endpoint at https://mcp.agentdomains.co,
    or the same server locally over stdio. Nothing to install for the hosted one.

    
20 tools: check availability, claim, list, records, forwards, proxies — same API key as the CLI.

    
No key yet? Connect with no key, call signup, then pass the key it returns as api_key on each call.


    

      

        
Hosted / one line

        
claude mcp add --transport http agentdomains https://mcp.agentdomains.co \
  --header "Authorization: Bearer adom_…"

        
Hosted / config file

        
{
  "mcpServers": {
    "agentdomains": {
      "type": "http",
      "url": "https://mcp.agentdomains.co",
      "headers": { "Authorization": "Bearer adom_…" }
    }
  }
}

      

      

        
Local / stdio

        
AGENTDOMAINS_API_KEY=adom_… npx -y agentdomains-mcp

        
Local / config file

        
{
  "mcpServers": {
    "agentdomains": {
      "command": "npx",
      "args": ["-y", "agentdomains-mcp"],
      "env": { "AGENTDOMAINS_API_KEY": "adom_…" }
    }
  }
}

// why agentdomains

    
Built for agents,
not dashboards

    
Every part of this is an API call or a CLI flag: the signup, the claim, the
    records, the certificates. A human could drive it from the docs, but it was written for
    something that reads JSON.

  


  

    

      
01 / CLI

      
One command

      
agentdomains claim myapp --email you@example.com --domain agentdomains.co and your domain resolves on the public internet in seconds. Add --json for clean machine output.

    


    

      
02 / SIGNUP

      
Signup needs nothing

      
signup hands your agent an API key with no email and no form. Registering the first name takes --email, used only for the confirmation link, the trial reminder, and notices about your names.

    


    

      
03 / HTTPS

      
Bring your own SSL

      
Point a domain at your server and Let's Encrypt HTTP-01 just works, or drop the ACME token in a TXT record for DNS-01.

    


    

      
04 / CHOICE

      
Two domains

      
Claim under agentdomains.co or makes.fyi with --domain. The same name can live under each.

    

  


  

    

      
// dns

      
A real zone, not a redirect

      
Each claimed name is a live DNS record you control — the same primitives a
      zone file gives you, minus the registrar. Update records with agentdomains record
      or the MCP tools.

    


    

      

        
01 / RECORDS

        
Four record types

        
Point a name at a server with A or AAAA, at another host with
        CNAME, and prove ownership or publish config with TXT — including
        ACME tokens for DNS-01 certificates. When you outgrow it, delegate the name to your own
        nameservers.

      


      

        
02 / FORWARD

        
URL forwarding

        
No server yet? Forward the name to any URL and the edge follows your agent's deploys —
        handy while output lives on a preview host. One API call to set, one to change, and the
        edge follows the new target within a minute.

      


      

        
03 / PROXY

        
Reverse proxy with HTTPS

        
App already running on a host like myapp.fly.dev? The edge reverse-proxies
        the name to it over HTTPS on our certificate, so visitors see your hostname in the address
        bar, never the origin's.

      

    

  


  

    
// use cases

    
What agents actually point these at

    
Four patterns cover most claims — the same CLI, the same
    20 MCP tools, the same HTTP API.

  

  

    

      

        
01 / DEMOS

        
Ship a demo with a real URL

        
Your agent deploys a prototype to a server and hands it over as a bare IP.
        agentdomains claim demo --domain agentdomains.co --type A --content 203.0.113.10 turns it into a link
        you can share, live on the public internet in seconds.

      

      

        
02 / APIs

        
Give an API a front door

        
Agent-built APIs need real hostnames for webhooks, CORS origins, and OAuth callbacks.
        Reverse-proxy the name at your backend and TLS terminates on our certificate:
        https://api-widget.agentdomains.co, nothing to install or renew.

      

      

        
03 / PREVIEW HOSTS

        
Forward while it moves

        
Output lives on a preview host today and a VPS tomorrow. URL-forward the name to wherever
        the build lives; when the agent moves, one call moves the name.

      

      

        
04 / PROVING GROUNDS

        
Certificates and ownership

        
Point a name at your own server and Let's Encrypt HTTP-01 just works, or publish the ACME
        token as a TXT record for DNS-01. The same TXT primitive answers domain-verification
        challenges.

      

    

  


  

    
// FAQ

    
Questions, answered straight

    
Straight answers, no asterisks. Full policy: pricing and the
    docs.

  

  

    

      

        
Is it free, or is there a catch?

        
Free for 30 days, then $1/month. Every new account gets a 30-day free trial: up to 10
        names under agentdomains.co or makes.fyi, every feature, no card.
        On day 25 we email a reminder. On day 30, names on accounts that have not upgraded are
        released for anyone to claim. The account stays, and upgrading lets you claim again.
        Pro ($10/year or $1/month) keeps your names as long as you pay, raises the cap to 100,
        and adds visitor stats. The other catch is the next question, on the
        compare page in full. More on pricing.

      

      

        
Do I own the domain I claim?

        
No. A name here is a subdomain of a zone we operate — no auth code, no transfer out, no
        registration record. The right trade for scaffolding an agent just produced; for a name
        that must carry a brand in two years, buy a real domain and keep this for experiments.

      

      

        
Can an agent run the whole thing without a human?

        
Almost, deliberately: signup is an unauthenticated API call that returns a
        key instantly, the CLI prints JSON with --json, and the MCP server exposes 20
        tools. A human shows up twice: clicking the email confirmation link on the first name,
        and paying for Pro to keep names after the trial. Agents can't accidentally charge you.

      

      

        
Any request quotas or bandwidth bills?

        
None on either plan: no request quota, no rate card, no overage. Signup and availability
        checks are rate-limited per IP to keep the pool from being farmed.

02 / TRIAL

        
30 days free

        
signup is instant and anonymous, with no card, and starts a 30-day
        free trial. Your first claim takes --email and we send a
        confirmation link. On day 25 we email a reminder with the end date. On
        day 30, names on accounts that have not upgraded are released for anyone to claim.
        The account and key stay, and upgrading lets you claim again.

      


      

        
03 / KEEPING IT

        
Pro keeps them

        
Pro is $10/year or $1/month. Your names are kept as long as you
        pay, and never removed for being unused, even when the server behind them goes quiet.

        and no bandwidth bill on either plan.
