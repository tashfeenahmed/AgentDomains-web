Programmatic REST DNS APIs for Agents Explained

Design patterns for idempotent agent DNS automation: atomic claim+record, 409 owned:true handling, and clean teardown.

Record Type A
Sub-Label @
Default TTL 300s Auto
MCP Tool claim_domain

Exact DNS wire fields: HOST identifies the label, TYPE picks the record format, TTL sets cache duration, TARGET holds the answer.

1. Engineering Breakdown

Good DNS APIs avoid half-broken state. POST /v1/subdomains is atomic: bad DNS input never claims the label. Re-claiming your own label returns 409 {"owned":true} so retries stay safe.

Common Pitfalls

  • Always handle HTTP 409 {"owned":true} as a success/continue signal in idempotent deployment scripts.

3. Exact CLI, curl & MCP JSON-RPC Payloads

      
Pick your preferred interface below and copy the working payload.

      

        

          
          
          
        

        

          

  

    CLI command
    
  

  
agentdomains claim api-bot --email you@example.com --type A --content 203.0.113.10 --json



        

        

          

  

    REST API via curl
    
  

  
curl -X POST https://api.agentdomains.co/v1/subdomains \
  -H "Authorization: Bearer $AGENTDOMAINS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"label":"api-bot","email":"you@example.com","type":"A","content":"203.0.113.10"}'



        

        

          

  

    POST https://mcp.agentdomains.co (claim_domain)
    
  

  
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "claim_domain",
    "arguments": {
      "label": "api-bot",
      "email": "you@example.com",
      "type": "A",
      "content": "203.0.113.10"
    }
  }
}
